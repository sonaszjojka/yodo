- Done (2026-11-05): roadmap 2.5: copy / paste / duplicate / select all (ADR 0039). Copy, cut and paste use the browser's clipboard events with a plain-text JSON payload (`yodo/clipboard`, version 1), so they work between drawings, tabs and reloads without a permission prompt; the payload is untrusted, so a pure validator keeps only well-formed elements and drops the rest. - Done (2026-11-05): roadmap 2.6: images (ADR 0040). Pasting an image file (screenshot or copied image) stores it through a new `ImageRepository`, keyed by the SHA-256 of its bytes, so identical images are stored once: IndexedDB `blobs` store (database version 2, existing drawings untouched) in hosted mode, and `PUT/GET /api/images/{hash}` with files under `<YODO_DATA_DIR>/images` in self-hosted mode (hash re-checked by the server, 10 MiB cap, PNG/JPEG/GIF/WebP only, atomic write). The drawing holds an `image` element with only the `fileId`; it is additive, so schemaVersion stays 1 (ADR 0013), and auto-save keeps `fileIds` in step with the elements. The renderer draws a grey placeholder until the picture loads, and one shared cache serves the canvas and Home thumbnails. Resize keeps the proportions; copy/paste of an image element works through the ADR 0039 payload. SHA-256 falls back to plain JS where `crypto.subtle` is missing (plain-HTTP LAN origins). Orphan blobs are not collected yet. Plan review: 3 findings accepted (stale missing-image cache, thumbnails, IndexedDB upgrade test). Code review: 2 bugs fixed (an upload still running when the editor closed was lost from the final save; an e2e poll accepted the placeholder), round 2 clean. Codex retest passed in hosted and self-hosted mode, light and dark.
- Done (2026-11-05): roadmap 2.9: Excalidraw import (ADR 0014). - Done (2026-11-05): roadmap 2.8: `.yodo` export / import (ADR 0013, 0040). A `.yodo` file is the drawing's JSON plus a `files` section holding each referenced image as base64; it needs no schema bump because `files` exists only in the file. `parseYodoFile` splits `files` off before the normal migrations run, checks every element (a bad one rejects the whole file) and requires each image element's picture to be listed. Import gives the drawing a fresh id, so importing your own export never overwrites it, and checks every image (type, size, that it decodes, that its bytes hash to the id the drawing uses) before storing any. A temporary **Export** button in the editor does the download until 2.7's dialog takes it over; Home has one **Import file** button that picks `.yodo` or Excalidraw by extension. Plan review: 3 findings accepted (images, a real migration test, strict element checks). Code review: a base64 regex overflowed the stack on large images (fixed); a further review of the image wiring found two bugs, both fixed (undecodable bytes accepted in hosted mode, stale image cache after import). Codex retest passed in hosted and self-hosted mode.
