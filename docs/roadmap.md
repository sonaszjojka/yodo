# Yodo — Roadmap

> Status: **approved 2026-10-30** (Stage 5 of `docs/plan.md`). Splits the MVP in `docs/product.md` into milestones and tasks of about one session each. Each task has a "done when…" criterion on top of the definition of done in `docs/conventions.md`. Every task is a GitHub Issue (linked after each task name; done tasks link the PR that shipped them) grouped in milestones M0–M5; the M2 and M3 issues were created when M1 ended. This file keeps the order and the milestone split.

## Ordering principle: walking skeleton first
M0 builds a thin end-to-end path through every part of the system (web app, Go server, SQLite, Docker image, Pages deploy, CI) before any feature work. Integration risks (Vite `base`, hash routing, `go:embed`, CI path filters) show up on day one, and from then on every task ships to a live URL. Features are added as vertical slices on top.

## M5 — Agents (MCP)
A local stdio MCP server in `mcp/` so agents can read and edit drawings (ADR 0061). Order: safe concurrent saves and API tokens first, then the package with read-only tools, then rendering, writes, diagrams, the hosted-app link and the release.

## Rules for changing this roadmap
- Tasks may be split, merged or reordered; record why in the commit message.
- A task that turns out bigger than one session is split before continuing.
- Anything new goes to `docs/product.md` "Later" first, not straight into a milestone.
